# 项目脚本开发规范

> 规范版本：v1.0  
> 适用范围：`script_download/`、`script_processed/`、`script_analysis/` 及后续项目脚本  
> 更新日期：2026-08-14

## 1. 规范目的

本规范统一项目脚本的命令行接口、终端进度、日志、文件安全和错误处理方式。新脚本提交前应满足本规范；若确有例外，应在脚本说明和对应文档中说明原因。

## 2. 参考实现

终端卡片和并发进度的基准实现来自：

- `script_download/cci_sm/download_cci_sm_passive_v092.py`
- `script_download/gleam/download_gleam_winscp.py`
- `script_download/era5_single_levels/download_era5_single_levels.py`
- `script_download/global_ai_pet_v3/download_global_ai_pet_v3.py`

后续脚本应复用这些实现中的设计原则，不应各自创造互不兼容的进度显示风格。

## 3. 命令行接口规范

### 3.1 必须提供

- `--help`：说明用途、输入、输出和示例。
- 明确的输入路径参数，例如`--data-root`、`--input-dir`。
- 明确的输出路径参数，例如`--output-dir`、`--log-dir`。
- 可选任务范围参数，例如`--dataset`、`--start`、`--end`。
- 明确的退出码。

### 3.2 推荐提供

- `--verbose`：增加诊断信息，但不能破坏实时卡片。
- `--workers`：并发脚本控制并发数。
- `--overwrite`：覆盖行为必须显式启用，默认不覆盖。
- `--checksum`或等价选项：耗时的完整校验默认关闭。

## 4. 终端卡片规范

### 4.1 卡片布局

交互式终端应使用约86列宽的边框卡片：

```text
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ DATASET STRUCTURE CHECK | READ-ONLY                                                    │
├──────────────────────────────────────────────────────────────────────────────────────┤
│ Source: ...                                                                            │
│ Output: ...                                                                            │
│ Progress: ███████░░░░░░░░░░░░░░░  33.3%  files 1/3                                  │
│ Current: dataset/group/file                                                            │
│ Status: PASS  pass=1 warn=0 fail=0                                                     │
│ Elapsed: 0s  metadata only                                                             │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

卡片至少包含：

- 标题和任务类型
- 输入源、输出目录
- 总进度条和百分比
- 当前文件或当前任务
- 成功、警告、失败计数
- 已用时间；下载或长任务可增加速度和ETA

### 4.2 颜色与状态

| 状态 | 颜色 | 含义 |
|---|---|---|
| RUN/进行中 | 青色或黄色 | 当前任务正在执行 |
| PASS/完成 | 绿色 | 当前任务成功 |
| WARN/警告 | 黄色 | 可继续，但需要记录或人工复核 |
| FAIL/失败 | 红色 | 当前任务未完成或结果不可用 |

状态文字不能只用颜色表达，必须同时显示文字标签，以适配无色终端和日志文件。

### 4.3 刷新与重定向

- 交互式终端使用ANSI光标控制原地刷新，建议刷新间隔不小于0.2秒。
- 卡片刷新期间，普通logger不得向stdout写行，避免覆盖卡片。
- stdout非TTY、管道或CI环境必须关闭ANSI控制符，改用逐行文本进度。
- Windows应尝试启用VT100；启用失败时必须仍能输出可读文本。
- 中文、全角字符和ANSI转义序列必须正确计算显示宽度，避免卡片边框错位。

### 4.4 进度估算

- 已知总量时显示百分比和`完成量/总量`。
- 总量未知时显示已完成任务数，不得伪造百分比。
- ETA在速度为零或总量未知时显示`--`。
- 速度应基于时间窗口或实际耗时计算，不能用单次瞬时值制造异常跳变。

### 4.5 交互式终止

- 具有终端卡片的长任务必须提供可发现的安全终止按键，统一使用`Q/q`；卡片中应显示“按 Q 停止”。
- 用户按下`Q/q`后，脚本应停止派发新任务，通知正在运行的任务尽快退出，并保留`.filepart`等可续传文件。
- 安全终止完成清理后使用退出码`130`，并在日志中记录“用户按 Q 终止”及恢复方式。
- `Ctrl+C`仍作为所有终端和非TTY环境的备用中断方式；捕获后同样清理卡片并保留可恢复文件。
- 非TTY、管道或CI环境不监听按键，仅保证`Ctrl+C`可中断。

## 5. 日志规范

- 日志文件统一使用UTF-8。
- 每条日志包含时间、级别和消息，例如`2026-08-14 16:38:19 | INFO | ...`。
- 终端卡片和日志文件分离；卡片负责状态，日志负责细节和异常上下文。
- WARN/FAIL必须包含文件名、数据集、原因和建议动作。
- 不把密码、Token、Cookie或私钥写入源码、终端或日志。
- 日志目录由脚本创建，不能依赖用户手工预创建。

## 6. 文件与数据安全

### 6.1 原始数据只读

- 原始数据必须使用读取模式打开。
- 不得在原始目录内创建报告、临时文件、缓存或解压文件。
- 输出路径必须在运行前解析为绝对路径，并验证不在原始数据目录内。
- 压缩数据应解压到临时目录；任务结束后清理临时文件。
- 默认不覆盖已有输出；覆盖必须由显式参数授权。

### 6.2 输出与临时文件

- 输出文件使用明确、稳定的文件名。
- 长任务建议先写`.partial`，成功后再原子替换为正式文件。
- 临时文件使用`tempfile`创建，禁止使用固定的系统路径或宽泛文件名。
- 报告应记录输入路径、版本、运行时间和处理参数。

## 7. 依赖与环境

- 每个脚本目录应提供`requirements.txt`或项目级依赖说明。
- 启动时检查关键依赖，并报告实际读取后端。
- 可选后端缺失时应给出明确WARN；不能静默跳过，也不能填充伪造元数据。
- 不在脚本中自动下载、升级或修改运行环境；环境安装由文档或部署流程完成。

## 8. 错误处理与退出码

建议统一使用：

| 退出码 | 含义 |
|---:|---|
| 0 | 成功完成，没有FAIL |
| 1 | 任务完成但存在FAIL或结果不完整 |
| 2 | 参数、路径、依赖或安全检查失败 |
| 130 | 用户中断（Ctrl+C） |

异常处理要求：

- 捕获可预期的单文件错误，记录后继续处理其他文件。
- 关键目录、配置或安全校验失败时立即停止。
- 不使用裸`except`吞掉错误；至少写入异常类型和消息。
- 终端显示简洁原因，日志保留完整堆栈或上下文。

## 9. 脚本交付前检查清单

- [ ] `--help`可用，示例命令可复制执行。
- [ ] 输入、输出和临时目录路径已明确。
- [ ] 原始数据只读保护已验证。
- [ ] 交互式终端显示卡片，stdout重定向时无ANSI乱码。
- [ ] 进度包含当前任务、总体进度、状态和耗时。
- [ ] 交互式长任务显示“按 Q 停止”，按键终止后保留断点文件并返回130。
- [ ] 日志写入UTF-8文件，且不覆盖实时卡片。
- [ ] 关键依赖有安装说明和版本记录。
- [ ] 成功、WARN、FAIL和异常退出码均已测试。
- [ ] 至少使用一个小样本完成冒烟测试。
- [ ] 输出文件、覆盖策略和可重复运行方式已写入`docs/`。

## 10. `01_datacheck`符合性说明

`script_processed/01_datacheck/check_structure.py`已按本规范实现：

- 使用86列卡片和进度条风格。
- 交互终端原地刷新，非TTY输出逐行进度。
- `data_raw`只读，输出目录越界时拒绝运行。

## 11. 本机运行基线与性能约束

本节记录当前项目运行电脑的已验证配置。后续脚本应以此配置为基线进行默认参数设计；如果换机或更换Python环境，应重新运行环境核验并更新本节。

### 11.1 已验证硬件与系统

| 项目 | 当前配置 | 脚本约束 |
|---|---|---|
| 操作系统 | Windows 11 x64，Build 26200 | 使用`pathlib`处理路径；禁止硬编码Linux路径和shell命令 |
| CPU | Intel Core i7-14650HX | 默认并发不超过4个CPU/IO任务；需要更高并发时必须提供参数并说明内存影响 |
| 逻辑处理器 | 24 | 不以24作为默认worker数，避免数据解码和磁盘IO过载 |
| 可用物理内存 | 约15.78 GB | 禁止一次性加载大型年度NetCDF或全球栅格数组；优先元数据读取、窗口读取和惰性计算 |
| 项目磁盘 | `F:`，约2.79 TB | 原始数据、处理结果和日志统一按项目目录分层 |
| `F:`剩余空间 | 约2.62 TB | 长任务开始前检查剩余空间；低于100 GB时应停止产生大文件并发出WARN |

### 11.2 已验证软件环境

| 项目 | 配置 |
|---|---|
| Python | 3.12.13，64-bit |
| Python路径 | 项目本地`.venv\Scripts\python.exe`；由`script_processed/01_datacheck/setup_environment.ps1`创建 |
| NumPy | 2.5.2 |
| pandas | 3.0.5 |
| xarray | 2026.7.0 |
| netCDF4 | 1.7.4 |
| rasterio | 1.5.1 |

核验命令：

```powershell
& .\.venv\Scripts\python.exe -c "import numpy,pandas,xarray,netCDF4,rasterio; from pyhdf import SD; print('readers ready')"
```

### 11.3 面向本机的性能规则

1. **避免全量载入**：GLEAM年度文件和全球栅格不得直接调用`.values`读取科学数组；只读取维度、坐标、属性，或使用窗口/块处理。
2. **并发上限**：默认`workers=4`；下载、解压、NetCDF解码和GeoTIFF处理不得无参数地创建24个任务。并发脚本必须提供`--workers`。
3. **内存预算**：单个任务目标内存不超过约2 GB；多个任务的总峰值应控制在可用内存的70%以内。
4. **磁盘写入**：临时文件优先写入项目外的临时目录或明确的`tmp`目录，任务结束清理；不得在`data_raw`内写临时文件。
5. **压缩文件**：GOSIF等压缩栅格采用流式解压或临时文件；禁止把全部年份解压后再处理。
6. **NetCDF策略**：优先使用xarray的惰性打开和netCDF4元数据接口；只有经过裁剪或分块后才读取数据数组。
7. **栅格策略**：优先使用rasterio窗口读取；MODIS HDF4使用pyhdf读取SDS元数据，正式裁剪再调用支持HDF4的工具链。
8. **进度刷新**：实时卡片刷新间隔不小于0.2秒；不得在高频像元循环中逐条打印日志。
9. **编码兼容**：文件和日志使用UTF-8；非TTY终端使用ASCII进度条，避免Windows传统代码页造成乱码。
10. **长任务恢复**：下载和处理脚本应支持跳过已完成文件、`.partial`临时结果或断点续跑，避免重复占用磁盘和网络。

### 11.4 本机运行命令约定

项目依赖统一安装在项目根目录的`.venv`中。项目文档和自动化命令必须优先使用项目解释器：

```powershell
& .\script_processed\01_datacheck\setup_environment.ps1
& .\.venv\Scripts\python.exe script_processed\01_datacheck\check_structure.py
```

禁止依赖系统`python`和裸命令`pip`中碰巧存在的包；安装和运行必须使用同一个项目解释器。脚本不得假设当前目录、用户主目录或环境变量一定存在；应根据脚本位置推导项目根目录，并允许用户通过参数覆盖输入、输出和临时目录。

### 11.5 配置变更记录

当发生以下变化时必须更新本节并重新执行冒烟测试：

- Python主版本、解释器路径或位数变化
- xarray、netCDF4、rasterio、pyhdf等读取后端升级
- 内存、CPU或项目磁盘变化
- 从本机切换到服务器、容器或云环境
