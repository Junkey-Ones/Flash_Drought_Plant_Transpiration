# 准备阶段验收

## 对照与取舍

| 对照 | 已采用的做法 | 当前缺口 |
|---|---|---|
| [Cookiecutter Data Science](https://cookiecutter-data-science.drivendata.org/v1/) | 原始数据、工作文件、交接数据与报告分层 | 在新环境中重建项目所需的环境锁和最小样例尚未落地 |
| [PyPSA-Earth](https://github.com/pypsa-meets-earth/pypsa-earth) 与 [Snakemake 部署文档](https://snakemake.readthedocs.io/en/stable/snakefiles/deployment.html) | 预留独立的工作流与配置目录，阶段依赖有明确分工 | 依赖仍需落实到可检查的入口。需要试跑配置、环境验收和端到端冒烟测试 |
| [Workflow Run RO-Crate](https://www.researchobject.org/workflow-run-crate/) | 设计了运行标识、输入清单、配置快照和阶段完成清单 | 需要固定最小清单字段、追溯方式和异盘恢复检查 |

当前目录能够承载 M0–M10，继续沿用。先在现有 Windows 环境跑通可重复的 M0–M2 小链路，再按实际需要确定编排工具。若选择 Snakemake，把 Windows 下的运行方式、F 盘访问和样例性能纳入选型验收。运行溯源先用本项目清单落地，论文归档时再评估是否导出通用交换格式。

## 开工门槛与验收证据

按表逐项验收。每项记录结论、证据路径和日期。必需项未通过时暂停对应生产步骤。可选输入单列，按协议确定影响范围。

| 顺序 | 工作 | 通过条件 |
|---|---|---|
| 1 | 固定协议来源 | 运行清单能定位预注册、技术手册、工程规格和原生数据 SOP 的版本与哈希。可共享的文件或快照随项目归档。受限文件记录可访问位置与校验值。未解决的科学口径冲突列入 M0。 |
| 2 | 固定配置和测试边界 | M0 审核参数、表契约、规范矩阵和种子。工作流显式区分 `test` 和 `production`，测试运行使用独立标识和目录，生产入口拒绝读取测试清单。 |
| 3 | 验证并锁定环境 | 用真实样例验证 NetCDF／GRIB、MODIS HDF4、空间数据和 Parquet 的实际读取或写出后端。记录 Windows、Python、底层库版本和安装步骤，锁定已验证环境，并在新环境重做最小测试。 |
| 4 | 做 M1 样例验收 | 核对 ERA5-Land 跨月小时轴、累计语义、符号和字段，核对已有 MODIS 地类样例的瓦片、QA 与 CRS。记录输入、判定、限制和补齐事项。历史数据盘点只作输入线索。 |
| 5 | 跑 M0–M2 小链路 | 从统一入口先预检，再用小范围试跑生成可核对的候表。检查相同输入续跑、失败后重试、输出校验失败、边界数据缺失及修改上游后的失效处理。记录资源峰值与可用并发。 |
| 6 | 正式事件链放行 | 核实 2000 年 ERA5-Land、研究区边界、动态物候与地类覆盖。逐产品登记许可、覆盖、版本和缺项。Q3 和可选分支的依赖分别放行，避免阻断已具备条件的主线环节。 |
| 7 | 归档并试恢复 | 将批准的协议、配置、环境锁、运行和产物清单、必要报告与不可轻易重取的输入列入归档。使用独立存储位置做一次最小恢复，验证清单与代表产物能读取且哈希一致。 |

## 清单最低要求

- **运行清单**记录清单版本、运行标识、模式、协议与配置哈希、输入清单哈希、代码与环境身份、研究域与分析范围、种子和开始时间。正式运行记录可定位的提交，核查参与运行的源码、配置及依赖没有未提交或未跟踪改动。未经固定的开发运行只用于测试。
- **阶段完成清单**记录阶段、分区、尝试标识、实际读取的上游产物标识及校验值、输出相对路径、字节数、校验值、表契约版本和验收结果。多文件产物逐成员列出或引用有校验值的成员清单。已通过的清单对应一套不可变产物。
- **发布和续跑**按清单发布。已被有效清单引用的文件不可原地替换。未完成发布的文件仍属未验收，只有在确认所属尝试且无人使用后，才可由责任阶段回收。续跑时核对实际依赖与产物完整性，校验失败的结果不得传给下游。

## Git 基线

Git 只保存脚本、文档和必要的仓库控制文件。旧数据目录占位文件和下载日志已从当前索引移出。既有提交中的对象仍属于历史记录。协议来源见 [FD-WT v1.3.1 协议来源登记](protocol_sources.md)。建立基线时核对暂存清单和凭据，分开整理新架构与旧脚本、旧文档的变更。
