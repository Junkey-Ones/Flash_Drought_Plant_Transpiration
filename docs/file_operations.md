# 文件操作与存放规范

适用于人工开发、AI 接手和自动化任务。路径归属以[文件架构表](file_architecture.md)为准。

## 1. 开工与读取

- **必须**先确认任务所属阶段、产品及数据版本、输入来源、输出位置和验收条件。读取已有文档和工作区变更，保留无关文件及修改。
- **必须**用项目根目录解析相对路径。写入前校验解析后的目标仍在该类文件的许可目录内，涉及链接或目录联接时也要核对实际目标。
- 分析任务**禁止**在 `data_raw/` 解压、缓存、改名、覆盖、删除或生成报告。授权下载任务以产品目录为单位追加，先校验下载结果，再登记来源、版本和文件校验值。
- 正式下游**必须**通过清单读取 `data/frozen/<run_id>/` 的有效产物。只知道文件名、修改时间或文件存在，均不足以确认产物可用。

## 2. 创建、命名与开发

- 新增工程文件使用小写 `snake_case`，源码、配置和日志使用 UTF-8。保留协议规定的表名、字段名和原始产品命名。脚本用用途命名，例如 `audit_era5land.py`。
- 科学参数来自 `config/` 的冻结配置。路径、年份范围和并发等运行设置由入口传入。Git 保存脚本、文档和仓库控制文件。运行配置、数据文件、日志和产物留在本地，冻结配置随运行归档。合成样本由测试代码生成。
- 大型格点表与事件表使用 Parquet，按需要用产品和年份分区。栅格用 NetCDF 或 GeoTIFF，矢量优先 GeoPackage。小型清单和报告用 CSV 或 JSON，运行日志用 JSONL。
- 改动字段、单位、主键、缺失编码或数据粒度时，必须同步更新表契约和受影响阶段。缺失、阴性和右删失分别编码。

## 3. 写入、校验与发布

1. 给本次执行分配 `run_id` 和 `attempt_id`，记录输入清单、配置、代码版本和环境。正式标识采用 `v1.3.1__{params_hash12}__{code_hash12}__{seed_id}`。同一标识只对应一套冻结输入和环境。若输入或环境改变会造成标识碰撞，先由 M0 重新冻结，使变更进入版本化配置。
2. 将计算产物写到 `data/interim/<run_id>/<stage>/<attempt_id>/`，日志写到同标识的日志目录。使用唯一的临时文件名或分区目录。
3. 验收时至少核对字段类型、主键、覆盖范围、缺失语义和所属阶段的科学质量检查。文件校验值及通过状态进入阶段完成清单。
4. 由责任阶段在目标卷内发布验收后的文件，最后原子写入完成清单。并发发布须互斥。下游通过清单校验本次输入身份和产物完整性后再使用。
5. 结果表、图、模型和报告写入对应的 `outputs/<run_id>/` 子目录。变更结果通过代码重建，禁止手工编辑冻结表或论文结果以修正差异。

## 4. 失败、续跑与清理

- 失败或中断要记录状态、原因、影响分区和恢复方式。保持未通过的产物处于工作目录。重试分配新的 `attempt_id`。
- 只有冻结输入和完成清单均匹配时，才可复用已完成阶段。输入、配置、环境或代码变化后按 M0 重新核定运行，重新计算受影响的阶段及其下游。
- 清理仅针对已确认可重建、且当前无人使用的指定工作目录。操作前核对解析后的绝对路径、所属运行和清理范围。历史运行的冻结数据、结果或审计记录按单独的归档决定处理。
- 日志不得包含凭据。错误记录包含阶段、运行及尝试标识、产品或分区、原因和动作。样本排除与质量判断另存审计表，协议变更另记偏离台账。

## 5. 交付检查

- 核对代码、产物、日志和报告均位于责任目录，并检查 Git 待提交列表。
- 运行与改动对应的验证，记录使用的是合成样本、真实样例还是正式数据。涉及科学口径变更时登记影响范围和重跑要求。
- 交接时给出已完成阶段、`run_id`（已运行时）、可复用产物、验收状态及后续工作。尚未运行或尚未验收的内容明确标记。
