# 项目脚本开发规范

适用于新增或修改的下载、阶段处理、统计分析、工作流和复核脚本。可直接运行的入口必须满足命令行、进度、日志和文件安全要求。内部函数通过调用入口报告进度，独立导入时保持无副作用。

## 1. 注释与使用说明

- 每个脚本的文件头必须说明所属阶段、用途、输入、输出、默认运行范围、可选运行方式、退出码，以及可直接复制的最小运行示例。注明上游依赖和下游使用的交接表。
- 公共函数和关键处理步骤必须写清参数、返回值、单位、数据粒度、缺失值含义和异常条件。涉及累计差分、候边界、事件阈值、删失或窗口未知时，说明规则缘由及对应协议条款。注释随代码同步更新。
- 每个入口必须提供 `--help`，列明所有公开指令和参数的用途、默认值、允许范围和组合限制。提供至少一个小范围试跑示例、一个正式运行示例，并说明试跑结果的位置。
- 下载入口参考现有 CCI 下载器的参数说明。正式阶段统一使用项目配置和工作流约定，帮助文本必须反映实际支持的参数。

## 2. 可控的运行范围与方式

| 参数或模式 | 要求 |
|---|---|
| `--config` | 正式阶段通过配置读取科学口径。日志记录实际使用的配置和版本。 |
| `--start`、`--end`、`--product` | 支持按适用的时期和产品缩小范围。帮助中写明起止边界是否包含。分区或样例上限按阶段需要提供。 |
| `--dry-run` | 显示实际参数、输入数量、预计任务和目标路径。允许读取必要元数据，禁止下载、计算产物或发布冻结结果。 |
| `--check-only` | 对适用的下载或校验入口执行只读检查，报告缺失、重复、损坏和不符合约定的输入。 |
| `--workers` | 并行入口须支持控制并发。非法值在开工前拒绝。 |
| `--progress auto\|plain` | 默认自动识别终端。允许手动切换为逐行进度。 |
| `--resume` | 需要续跑的入口须校验运行身份和阶段完成清单。下载续传还须校验原始来源与已下载部分。 |

输入输出路径和运行方式必须可核对。正式入口统一解析项目根和目标目录。缩小输出时仍须读取算法所需的上下文，例如跨月累计边界、气候基准期或事件随访。无法满足上下文时明确报错，局部试跑与正式产物分开归档。

## 3. 动态进度条与任务汇报面板

交互式终端必须原地刷新进度面板。参考 CCI 和 ERA5 下载器 `ProgressDisplay` 的总进度条、并发槽位和状态行。新增入口共用一套进度展示接口，处理逻辑只上报状态。

| 面板区域 | 必须显示 |
|---|---|
| 标题 | 阶段、运行方式、产品和范围 |
| 总进度 | 进度条、百分比、已处理量／总量及计量单位 |
| 当前任务 | 正在读写的文件、分区或处理步骤，并发时显示活跃任务和各自状态 |
| 运行统计 | 成功、跳过、警告和失败数，已用时间，有足够信息时显示速度和预计剩余时间 |
| 最终摘要 | 完成、部分失败、失败或中断状态，以及产物和日志路径 |

- 总量未知时显示活动指示和已处理数，预计剩余时间显示 `--`。统计以实际工作为准，发生失败时保留失败数和最终状态。
- 刷新建议限制在每秒 2–5 次。长时间等待下载、读取或计算时，持续更新耗时和当前步骤。并发任务集中汇报，由主线程刷新面板。
- 非交互终端、输出重定向或 ANSI 不可用时，按阶段、状态变化和间隔输出纯文本进度。状态标签可脱离颜色阅读，窄窗口及中文对齐须可用。
- 所有入口支持 `Ctrl+C` 安全中断。支持按键监听的交互长任务提供 `Q/q`，并显示提示。中断后停止派发新任务，记录状态，保留安全续跑所需的文件，恢复终端显示。

参考实现见 [CCI 下载脚本](../script_download/cci_sm/download_cci_sm_passive_v092.py) 和 [ERA5 下载脚本](../script_download/era5_single_levels/download_era5_single_levels.py)。这两份脚本用于参考面板布局和状态汇报，正式阶段的日志格式和发布规则以本规范为准。

## 4. 日志与退出码

- 阶段日志写入 `logs/<run_id>/<stage>/<attempt_id>/run.jsonl`。下载日志按产品放入 `logs/download/<product>/`，每次尝试有独立记录。统一使用 UTF-8，每行一条结构化事件。并发任务经同一日志写入端汇总。
- 每条事件至少有 UTC 时间、级别、事件名、阶段或脚本标识、运行及尝试标识、消息。涉及单项任务时记录产品、分区或文件。按需记录计数、耗时、异常类型和处理动作。
- 启动记录包含解析后的参数、输入范围、模式、代码与环境版本。结束记录包含成功、跳过、警告、失败数、耗时、验收状态、输出和日志路径。
- `INFO` 记录开始、阶段切换和完成，`WARNING` 记录可继续的异常，`ERROR` 记录失败及影响范围，`DEBUG` 记录按需排障信息。未预期异常保存堆栈，凭据、请求令牌及认证头必须脱敏。
- 进度面板与日志分开。刷新期间普通日志通过文件记录，终端按需显示摘要，避免打乱面板。科学质量检查、样本排除和偏离记录各归对应审计表。

| 退出码 | 含义 |
|---|---|
| `0` | 请求的运行模式成功完成，所有必需检查通过 |
| `1` | 执行失败或存在未完成的必需任务 |
| `2` | 参数、配置、路径、依赖或开工前检查失败 |
| `130` | 用户中断 |

## 5. 文件权限与产物安全

- 分析及审计入口只读 `data_raw/`。原始库禁止写入缓存、解压副本、临时文件、日志或报告。授权下载任务只在指定产品目录追加校验后的源文件。已存在的源文件冲突时报告并停止发布，替换须有明确授权和记录。
- 开工前核对输入、输出、日志及临时目录的实际绝对路径，检查路径穿越、符号链接和 Windows 目录联接。输出路径落到源数据、上游冻结表或无关历史运行目录时拒绝执行。
- 默认拒绝覆盖已存在产物。计算结果先写本次尝试的工作目录，验证后由责任阶段发布。正式交接以完成清单为准，失败、中断和部分输出不得成为下游输入。
- 网络下载按任务范围限流，重试设上限。只重试可恢复错误，记录次数和原因。批次处理允许继续检查其他独立分区，必需分区失败时返回失败状态。
- 启动时检查关键依赖与读写权限。脚本运行期间禁止自动安装或升级依赖。依赖锁定、日志路径、续跑和清理按[文件操作与存放规范](file_operations.md)执行。

## 6. 本机配置与资源预算

项目开发机配置记录于 2026-11-07。生产脚本启动时必须重新检测实际可用资源，尤其是内存、并行额度和目标卷剩余空间。下表用于制定试跑方案。

| 项目 | 本机实测 |
|---|---|
| 系统 | Windows 25H2，内部版本 26200 |
| 处理器 | Intel Core i7-14650HX，当前环境可见 24 个逻辑处理器 |
| 内存 | 当前运行环境报告约 15.7 GiB 内存预算，物理安装容量未单独核实 |
| 独立显卡 | NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB 显存 |
| 项目盘 | F:，NTFS，容量约 2794.5 GiB，采集时剩余约 2487.2 GiB。介质类型和持续读写速度待实测 |

### 开工前检查

- **先估峰值，再选并发。** 按变量数、形状、数据类型、解压后的数组大小、临时副本和输出缓冲估算内存。并行时计入父进程、每个工作进程及进程间传输。以当前系统可用内存和进程额度中较小的数为上限，初次试跑按其约 60% 控制全任务峰值，给系统和其他应用留出余量。估算不足以支持单任务时先缩分块或改用分批处理。
- **预留磁盘峰值空间。** 分别核算目标卷上的解压副本、中间表、待发布副本和最终产物，保留安全余量。日志记录估算量和实际可用量。空间不足时在批量写入前退出，并在长任务的分区边界复查。临时数据放本次尝试的工作目录。
- **先跑代表性样例。** ERA5-Land 优先用跨月样例，MODIS 用代表性瓦片和 QA 解码，模型用代表性样本和分块。记录阶段、样例范围、并发、分块大小、耗时、峰值内存及吞吐。未验证的资源预算只用于小范围试跑。

### 如何用好这台电脑

- **CPU 与并发。** 用同一代表性样例先测 1 个工作单元，再比较 2、4 个工作单元。只有吞吐仍提升、内存和磁盘都允许时再提高。实际并发取用户上限、测得的内存承载量、当前可用 CPU 额度和输入输出实测上限中的最小值。多进程运行时默认将每个进程的 BLAS／OpenMP 等底层线程限制为 1，避免两层并行相乘。Windows 进程入口使用 `if __name__ == "__main__":`，优先传路径和分区键，由工作进程打开自己的文件。
- **内存和读写。** M2 按月或空间分块读取必要变量，保留跨月累计所需边界记录。M3–M6 的分块必须保留各自需要的完整基准期、连续事件轨迹和暴露窗口。大表按分区增量写出，限制排队任务和同时打开的文件数。若吞吐随并发增加而停滞，降低并发并优先减少重复读取、小文件和进程间数组复制。
- **GPU。** 下载、解压、文件读取及常规事件扫描默认用 CPU。仅对已有 GPU 后端、计算密集且能分块装入显存的步骤评估 GPU。试跑比较端到端耗时和结果一致性，计入 CPU 与显卡之间的数据传输，再决定是否启用。
- **可调整、可复现。** 适用的批处理入口提供 `--workers` 和分块或批量大小控制。进度面板显示实际并发和当前分区，长任务按间隔记录吞吐、内存和磁盘使用情况。性能参数的变更不得改变事件资格、科学时间窗或数值口径。并发与分块改动后，核对输出行数、主键和代表数值。

## 7. 测试通过后才能提交

每次新增或修改脚本，提交前必须执行适用检查，并保存实际验证结果。

1. **接口检查。** 运行 `--help`、无效参数和小范围 `--dry-run`。核对帮助示例、计划范围、实际读取范围和退出码。
2. **正确性检查。** 用小型合成样本核对预期结果。涉及真实格式、质量标记、时空坐标或累计字段时，再使用通过读取验收的真实样例。
3. **可观察性检查。** 实际运行终端面板，检查实时刷新、并发状态、最终摘要和日志。重定向输出验证纯文本模式。
4. **安全与恢复检查。** 覆盖与改动相关的非法路径、写入原始库、已有文件冲突、失败或中断、重试和重复执行。核对源数据与上游冻结产物保持原样，失败运行没有发布完成清单。
5. **资源检查。** 批量入口须记录代表性样例的耗时、峰值内存、磁盘占用和吞吐，核对计划并发与分块大小适配本机。修改并发或分块策略时，核对与单工作单元的结果一致性。
6. **提交检查。** 核对改动清单，确认无原始数据、生成文件或凭据。记录执行指令、样本范围、通过情况和未覆盖项。缺少必要验证时明确标记待验收，禁止作为通过验收的脚本提交。
